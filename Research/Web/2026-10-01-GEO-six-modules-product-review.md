用户最新定位为“GEO企业客户的内容创作、分发、客资监控的智能化企业AI落地应用平台”。据此提出四个主业务板块：企业知识库、AI内容创作、矩阵分发、客资中心，另设轻量工作台。以下第2至11节保留为早期七板块方案与研究记录；当前精简范围以第12节为准。此处将“客资监控”理解为询盘、私信、表单等潜在客户线索，尚非用户单独确认的定义。

## 1. 五个网站考察记录

截至2026-10-01，证据等级分别为公开页面直接观察、官方文档描述、用户提供信息、待后台实测。官方自述不是独立性能验证。

### 蚁小二

来源：[首页](https://www.yixiaoer.cn/)、[企业API](https://www.yixiaoer.cn/customized)、[CLI](https://www.yixiaoer.cn/cli)。

已观察公开能力：

- 首页列出用户要求的12个平台名称，包括企鹅号、CSDN、简书；这不等于每个平台的每种内容都支持同一API流程。
- 多账号、图文/视频/文章、账号分组、团队和成员权限、统计、发布记录。
- 公开宣称账号/发布/数据API，OEM、功能定制与私有化部署；具体商务条件未取得。
- CLI明确暴露账号查询、字段schema、素材上传、validate、dry-run、正式发布、草稿和任务记录。
- 云端与本机发布可选择；API Key需要在客户端登录后取得。

产品决策：把蚁小二提升为国内矩阵发布的优先商务与POC候选。先评估购买API，待租户隔离、12平台能力矩阵、回执与费用确认后再考虑OEM。开源发布工具保留为备用，首版不必自行维护12套平台适配。

对接需确认：每个平台支持哪些内容；API与客户端功能是否相同；定时/封面/草稿/回查；公开URL返回；失败回调或轮询；数据指标；客户账号隔离与退出导出；调用/账号/团队费用；白标和服务SLA。展示指标与市场地位宣传不作为本报告评估证据。

## 2. 七个板块的最终定位

| 板块 | 回答的问题 | 子模块 | 核心产出 |
|---|---|---|---|
| 监控与洞察 | 市场和AI现在如何描述我们？差距在哪里？ | 采购问题库、AI可见度、原始回答、引用、竞品、事实错误预警、诊断机会 | 带证据的机会/问题单 |
| 企业知识库 | 企业和产品有哪些可核实、可使用的知识？ | 企业品牌、产品型号/参数/工况、技术文档、资质案例、采购FAQ、中英术语、原始素材、证据、权限和版本 | 经核准、可追溯、跨模块复用的知识资产 |
| 内容创作 | 应该写什么，怎样形成适合各渠道的内容？ | 选题与主题组、Skill智能体、知识检索、主稿、图文/视频、翻译、内容审核与版本 | 经核准且可多端改编的内容资产 |
| 网站与SEO | 内容能否被检索并承接采购需求？ | 抓取/索引问题、技术审计、产品和应用页、结构/内链、双语、实施/回滚、转化入口 | 已上线页面、变更记录与复测 |
| 信源与媒介 | 应在哪些外部来源建立可信信息？ | 引用来源库、真实机构/合作资料、媒体目录、报价/组合、预算审批、订单、留存 | 有依据的渠道方案和采购凭证 |
| 矩阵发布 | 如何可靠地把核准内容送到账号与渠道？ | 12平台账号、能力矩阵、素材适配、排期、预校验、发布/回查、异常重试、数据同步 | 公开URL与可追溯状态 |
| 效果与复盘 | 做了什么？带来什么变化？接下来做什么？ | 交付进度、发布/引用/流量、询盘CRM、成本、实验、月报、下期计划 | 可解释的效果与下周期行动 |

### 模块边界

- 监控记录外部状态与初步诊断；复盘关联“实施动作、费用和结果”。两者可以读取同一观测数据，不各算一套指标。
- 企业知识库负责原始资料、事实核准与知识版本；内容创作负责选题、表达和成稿审核。生成稿件不能自动回写为已核准事实；稿件中的新信息需经过入库审核。
- 内容生产经核准资产；发布负责版本在外部渠道的执行与回执，不独立再生成一份失去来源的文案。
- 媒介负责选择渠道、采购和商务履约；发布负责已选渠道的实际投递。媒体编辑接稿可用人工交付任务，不强求所有媒介有自动发布API。
- 网站SEO负责诊断和实施；品牌事实由知识库提供；文章正文由内容中心维护，发布至CMS后保存映射。
- 诊断规则分属各专业模块，但行动项统一进入首页工作台，避免出现多个待办孤岛。

## 3. 独立企业知识库与跨模块行动中心

### 企业知识库：独立入口，共享知识来源

企业知识库具有独立一级入口和管理界面，建立企业/品牌/产品/型号/市场/语言/采购角色/事实/证据/术语/素材的共同关系，由监控诊断、内容创作、网站SEO和媒介资料准备共同调用。账号授权仍由矩阵发布管理。

借鉴WorkFX的Brand DNA并扩展为“品牌定位 + 产品事实 + 采购场景 + 技术证据 + 渠道表达”。产品技术事实优先于营销风格。

建议二级菜单：

| 二级菜单 | 管理内容 |
|---|---|
| 企业与品牌 | 企业介绍、品牌定位、能力范围、目标市场和受众 |
| 产品与技术 | 产品系列、型号、参数、单位、工况、选型与技术文档 |
| 资质与案例 | 认证、专利、检测材料、应用案例、授权范围和有效期 |
| 客户问答 | 销售FAQ、工程师问题、采购顾虑和经核准答案 |
| 术语与表达 | 中英术语、品牌/型号固定译法、表达边界 |
| 文档与素材 | 手册、表格、图片、视频、原始文件、来源和使用权限 |
| 知识审核与版本 | 待核准、冲突、过期、变更、公开级别和责任人 |
| 知识检索与问答 | 带出处的查询，无法确认时展示资料缺口 |

入库流程：上传/导入 -> 解析与归类 -> 抽取事实 -> 人工核准 -> 可用知识版本 -> 提供给Skill与其他模块。每条关键事实保留来源定位、适用型号、条件与更新时间。

产品参数、认证或案例更新时，生成受影响文章、页面和视频文案的修订任务；不直接覆盖已发布内容。知识权限按客户和公开范围隔离。

### 诊断与行动中心

默认首页展示：本周机会、待客户补资料、待技术审核、网站修复、待发布、媒介预算待批、失败任务、待复测。

每个任务有：来源发现、关联产品/问题/页面、负责人、优先级、截止时间、预计费用、交付物、验收、复测时间、状态与证据。

不是建议重新建立大型项目管理软件。先做贯穿七模块的任务对象，必要时同步客户已有飞书/企业微信/工单系统。

## 4. 端到端示例

示例主题：“某类镁合金零件在特定环境下如何选择表面处理方案”。仅为演示，不是对华清技术效果的验证。

1. 监控：保存同一采购问题在目标AI的回答与引用，发现客户未出现或描述不准确。
2. 行动：创建问题单，区分技术事实缺失、页面缺失、抓取问题、外部信源缺失。
3. 知识：关联经核准的工况、基材、处理流程、测试标准与案例；证据不足先补资料。
4. 内容：形成技术选型主稿、FAQ、英文摘要和视频脚本；技术人员批准。
5. SEO：建立对应HTML应用页面，完善内链与询盘入口，保存变更。
6. 媒介：依据实际引用来源与行业受众选择合适技术渠道，取得报价与客户批准。
7. 发布：官网及适合自媒体投递，收回任务状态和公开URL；媒体合作保留编辑回执。
8. 复盘：按原问题集重复采样，检查事实准确性、引用变化、产品页访问与询盘，决定下轮动作。

任何一环未完成，不跳到“已带来AI推荐”或“已贡献收入”。

## 5. 媒介模块的优化重点

媒体可信信息、媒体编辑来源、企业账号和转载页面分开分类。给供应商打内部采购分可以，但不命名为“AI官方信任分”。

每个来源记录：行业相关性、发布主体、页面可访问性、真实编辑/事实证据、引用过它的AI与问题、引用观察时间/样本数、合作方式、价格与有效期、留存与询盘表现。

信息不足显示“未采样/未核验”，不能填0造成假精度。大量同源转载先聚类，再统计独立来源。

复盘后更新采购优先级；单次引用相关性不能证明该次付费发稿导致推荐。低预算候选与套餐参见集成方案V1，仍需真实报价。

## 6. 发布层选型更新

新优先级：

1. 蚁小二API/CLI做12平台发布POC，核对实际内容类型和费用。
2. 自研客户、知识、审批、排期和供应商适配接口；账号与发布结果能导出。
3. 已有工具覆盖不足或商务不合适时，再补Wechatsync/social-auto-upload或正式平台接口。
4. 海外平台按蚁小二实际覆盖与Postiz等候选比较，不从首页图标推断完整API支持。

标准接口建议：listAccounts、getCapabilities、validate、uploadAssets、createDraft、schedule、publish、getStatus、fetchMetrics。供应商不同，业务对象保持统一。

统一发布包字段：tenant_id、brand_id、product_id、campaign_id、content_id、content_version、approval_id、target_account、content_type、assets、schedule_at、idempotency_key。

发布适配层返回原始任务ID、标准状态、URL、错误类别和费用；收到回执后再按状态更新，API接收不等于公开发布。

## 7. 与现有合作内容系统的接口边界

若云端GEO内容质量和合作条件合适，可先作为生成服务，不必重写完整内容引擎。需要可传入核准事实、任务模板、目标平台，并可返回正文、引用证据、token成本和版本。

内部保留知识库与内容版本主记录；供应商生成不是事实核准。必须支持账号权限、客户数据隔离、资料导出、API价格和服务退出安排。

对比测试材料：一套获授权产品资料，同样的问题与输出要求。验收参数准确性、工况限制、中英文术语、证据定位、人工修改时间和单次成本；不只比较文章读起来是否顺畅。

## 8. 验收标准与开发顺序

P0：独立企业知识库入口与企业/产品事实管理、固定问题库、内容审核、一个网站CMS路径、蚁小二少量账号POC、引用证据、客户报告。

P1：扩至完整12平台能力清单、视频、媒介订单、CRM、内容变更追溯、成本控制。

P2：多行业配置、进阶实验、跨周期内容衰减、经销商资料同步和多供应商切换。

最小验收：一条真实采购问题，能一路定位事实、内容版本、网站/渠道URL、费用和复测结果；两个客户之间不能互读资料或发布账号。

用户已表示会自行登录云端GEO、WorkFX与Trendee。目前未观察到登录成功，后续补充实际后台证据：

- 云端GEO：知识上传/产品上下文、生成编辑、模板、审核、批量、token记账与API。
- WorkFX：品牌创建、问题到内容、排期、Technical Audit实际动作边界、GA4/查询级指标、当前可用功能。
- Trendee：Citations计算口径、源URL与原始回答、采样渠道、竞品/时间比较、Action Center如何落任务。

不在试用中上传客户机密、购买套餐、对外发文、修改真实网站或联系供应商。任何测试项目采用用户明确允许的资料与范围。

## 10. 自我复盘：当前方案需要收紧的地方

本节为2026-10-01的方案评审建议，不新增外部产品事实。七个主板块保持不变。

### 对前期建议的修正

1. 功能与工具清单偏多，容易误导成首版必须同时集成多个完整系统。现阶段应优先验证一条客户交付链，再选择组件。
2. 对接蚁小二、云端GEO以及采用开源监测底座都是候选决定；尚缺真实账号测试、API商务条件、数据出口和单位客户成本，不能写成定案。
3. “AI可信度”“精准归因”“自动优化”需要拆成可核实行为：实际引用样本、来源标记、可执行改动及其权限。不能把这些名称直接当已实现能力。
4. 制造业范围可以通用，但首个试点应只落一条产品线或一个采购场景。通用底座并不要求首次就证明适合所有行业。
5. 导航按七板块组织，日常运营按项目/产品/问题/任务组织。否则员工仍需在七个页面手工搬运信息。

### 十项优先优化

| 优先级 | 当前缺口 | 改进 | 所属板块/共享位置 | 可验证结果 |
|---|---|---|---|---|
| P0 | 客户目标容易停留在品牌曝光 | 项目启动明确重点产品、目标国家/角色、采购阶段、期望询盘类型和交付范围 | 项目首页 | 所有内容和费用都有对应目标；不把无关流量当成果 |
| P0 | 问题库可能主要由模型虚构 | 记录问题来源：销售FAQ、真实询盘、站长搜索数据、行业研究、模型扩展；人工确认优先级 | 监控与洞察 | 真实需求和合成问题能分开，基线集合有版本 |
| P0 | 建库和客户补资料成本高 | 先做一个产品系列的最小事实包，自动列资料缺口，指定客户技术核准人 | 企业知识库 | 不依赖全企业资料齐备即可启动，缺失项不编造 |
| P0 | 文章生成多但采购价值不清楚 | 用产品×采购角色×决策阶段建内容地图，先优化已有好页面，再新增内容 | 内容创作/网站SEO | 每篇有目标问题、独特证据、关联页面和下一步入口 |
| P0 | 首页待办仍可能是静态报告 | 从诊断直接创建含证据、交付物、预算和复测条件的任务 | 诊断与行动中心 | 无需重录就能交给写作、网站或媒介人员执行 |
| P0 | 客户审核可能拖住自动化 | 设置事实核准人与内容审批人；批量审批相同事实的派生稿；内容变化重新审核；超时提醒不自动视为同意 | 企业知识库/内容/发布 | 看得见等待时间、阻塞责任和核准版本 |
| P0 | 多平台发布数量会替代质量 | 支持12平台，但按客户选核心渠道；保证主稿质量、渠道适配和去重；每次发布关联主稿 | 矩阵发布 | 主稿数、派生数、成功发布数分别计量 |
| P0 | 费用和产出没有统一账本 | 记录模型/搜索/采样/发布/人工/媒体费用，设置客户预算上限与任务取消机制 | 共享成本/效果复盘 | 能算单客户交付成本，不因重试或全量扫描持续超支 |
| P0 | GEO效果容易被波动与归因误差放大 | 固定问题集、重复采样，保存失败率和模型/采集方式变更；来源不明询盘保持未知 | 监控/效果复盘 | 能区分观测变化、执行成果和可识别业务结果 |
| P1 | 渠道采购和长期内容维护不足 | 媒体试投设预算/复盘日期；保留证据后决定续投；产品更新触发内容修订 | 信源媒介/知识/复盘 | 不持续买无依据的曝光，旧内容可追踪修订 |

### 问题库与内容规划的进一步约束

- 固定核心问题集用于比较趋势；探索问题单独统计。无历史基线的新问题不混入历史增长率。
- 低搜索量的工业采购问题不自动判为低价值，结合销售团队对成交相关性的判断。
- 对不同平台的API和网页观测分开比较，采集条件改变时标记时间线；失败不能写成品牌未被推荐。
- 内容先分“已有页面需完善”“需要新页面”“适合第三方说明”“适合视频展示”，不默认每个问题都新写文章。
- 每个关键采购主题至少能定位一个主页面；衍生文章有自己的受众价值，不靠机械改写铺量。
- 主页面可以公开技术资料，同时提供可选选型咨询/资料下载入口。不要把所有核心技术信息藏在登录或留资之后。

### 数据对象和证据关联

至少打通：客户 -> 产品 -> 目标问题 -> 核准事实 -> 内容版本 -> 发布URL -> 观测记录 -> 行动任务/费用。

询盘通过内容链接、活动参数、引荐来源、销售核验或用户自报关联；无法确定时记录未知。问题与页面的规划关联不代表已经知道真实访客向AI输入了哪个问题。

同一事实被多篇稿件引用时共享fact_id；派生内容保留parent_content_id；发布引用已批准版本。版本过期时提示并生成修订任务，不静默改写历史报告。

### 报告分成三层

| 层 | 指标示例 | 用途 |
|---|---|---|
| 可控交付 | 已核准事实、完成的页面改动、合格主稿、公开发布、响应时间 | 合同验收 |
| 市场观察 | 搜索表现、AI提及/引用/事实准确性、来源变化、有效样本量 | 判断趋势和下一轮策略 |
| 业务结果 | 有效询盘、技术咨询、样品、报价、商机阶段、可识别收入 | 与客户销售团队共同复盘 |

不把三层压成一个无法解释的总分；制造业销售周期长，首月不以成交额作为唯一验收。

## 11. 收敛后的首版与验证门槛

### 七个板块都保留，实施深度不同

- 监控与洞察：固定小问题集、少量目标AI渠道、原始回答和引用、基本诊断。
- 企业知识库：单产品系列事实、文档来源、核准和公开权限。
- 内容创作：技术主稿、FAQ、渠道派生和一种视频流程，少量稳定Skill。
- 网站与SEO：单一CMS路径、核心产品/应用页、基础技术问题、询盘入口。
- 信源与媒介：可人工维护的来源/报价/凭证台账，不急建撮合交易市场。
- 矩阵发布：少量真实账号跑通，12平台保留能力清单与扩展位。
- 效果与复盘：执行记录、观测趋势、询盘导出和简单成本表。

### 首轮先验证四件事

1. 内容是否准确：使用同一套获授权资料，选择含参数、工况、选型、案例及中英术语的任务。比较人工修改时间和错误类型；关键参数无证据或型号混用的稿件不得发布。
2. 发布是否可靠：验证图文/视频、草稿/排期、失效登录、失败回查和重复任务；记录真实成功率，未完成实测前不宣称支持稳定自动发布。
3. 数据是否可追溯：随机选一项报告指标，能返回有效样本、采集条件、原始回答与引用；随机选一篇稿件，能返回核准事实和发布回执。
4. 经营是否成立：记录资料整理、技术审核、编辑、发布异常处理的工时，加上各供应商费用，估算可承受的客户数量与服务价格。

供应商接入门槛：同一测试任务可执行、数据可导出、接口与套餐边界明确、租户与账号隔离可验证、退出时客户资产可取回。接口缺失可先通过人工导入或发布包交付，不承诺已经自动贯通。

### 暂缓建设

全行业海量模板、12平台全面无人值守、复杂多Agent自治、自建完整CRM、自动媒体下单交易市场、无证据的AI综合权威分，以及在流量不足时声称能提供严格因果归因。

### 首版成功标准

在选定产品和采购场景中，团队能用同一系统完成建库、诊断、核准内容、网站修改、渠道发布与复盘；每一步有证据，客户等待与交付成本可见。之后再根据真实瓶颈增加自动化。

## 12. 最新定位下的精简方案：四个业务板块与轻量工作台

本节根据用户2026-10-01最新澄清制定，取代前述七板块作为首版建设范围。用户要的是面向企业客户的内容创作、分发和客资监控AI应用平台。此处把客资监控理解为合法获取的客户咨询与销售线索，并非竞争情报或AI品牌提及监控。

### 产品定位

基于企业知识自动辅助生产可信内容，分发到企业渠道，集中接收与识别潜在客户咨询，帮助人工及时跟进，并以轻量GEO观测改进内容。

核心链路：企业知识 -> AI内容 -> 审核分发 -> 客资收集 -> 分配跟进 -> 将高频问题经审核沉淀回知识库。

品牌被AI提及/引用是内容表现指标；真实咨询和留资才是客资事件，二者分别统计，不做一对一必然转化承诺。

### 四个业务板块

| 板块 | 首版保留 | 暂不做 |
|---|---|---|
| 企业知识库 | 企业/产品资料、FAQ、参数与证据、图片视频素材、知识核准、公开权限与版本 | 复杂知识图谱、全企业知识工程、重型PIM/ERP |
| AI内容创作 | 产品介绍、选型问答、案例三类核心Skill；中英按需；主稿、平台改编、封面/视频脚本、人工审核；基于已有视频素材的轻量剪辑可后续接入 | 大型Agent市场、全自动长视频/现场素材生成、通用设计平台 |
| 矩阵分发 | 授权账号、图文/视频发布包、排期、渠道校验、发布回执/URL、失败处理；官网作为可选CMS渠道 | 同时自研12个平台适配、全平台无人值守、复杂媒体交易市场 |
| 客资中心 | 授权渠道咨询接入、表单和人工导入、去重、来源/意图/产品标签、人工确认的意向分级、分配/提醒、状态、回复草稿、导出/轻量CRM同步 | 自建完整CRM、报价订单财务、未经授权的联系方式采集、默认自动群发或触达 |

工作台展示待审核、待发布、发布异常、待跟进、内容/渠道表现、可识别询盘来源和简要GEO趋势。企业切换、权限、授权、费用限额和日志放在公共设置，不算新增主板块。

### 七板块如何收敛

| 原板块 | 处理 |
|---|---|
| 监控与洞察 | 拆开：少量固定问题的GEO抽样与引用查看并入工作台；真实咨询监控进入客资中心。暂缓全行业竞品大盘、复杂声量和实时全平台采样 |
| 企业知识库 | 保留独立一级板块 |
| 内容创作 | 保留主业务，优先事实准确与少量稳定Skill |
| 网站与SEO | 取消独立板块：标题、描述、结构、内链建议、图片说明融入内容；官网CMS融入分发。全站性能/代码改造、迁移、外链工程作为专项服务 |
| 信源与媒介 | 取消独立板块：保留可人工维护的渠道资源表、报价和发布凭证；付费采购为按需服务，后续有订单量再系统化 |
| 矩阵发布 | 保留主业务，优先验证蚁小二等供应商，不把官网声明当实测承诺 |
| 效果与复盘 | 合并轻量工作台：内容/发布、AI表现、客资三类指标，不建设独立复杂BI |

### 客资中心的边界与自动化

首版客资包括自有表单咨询、官网留言、得到账号授权且接口支持的私信/评论咨询、人工登记和CRM导入。评论不自动算有效线索，点赞/浏览/AI提及不作为客资。

平台接入按“可公开发文”“可读私信”“可读评论”“可回消息”“可读统计”分别核查。蚁小二公开页提及抖音/视频号私信评论能力，但其企业API是否提供、需要哪些权限与费用仍待验证，不能推断12个平台客资可全量统一读取。

自动化优先：去重、提取产品和需求、标签与待确认意向等级、分配建议、跟进提醒、基于知识库拟回复。具体技术条件、承诺、价格与交期仍由人工确认；无证据不猜测公司/职位/联系方式。

最少字段：客户标识、渠道账号、原始咨询、时间、关联产品、来源URL/内容（若可确定）、联系人自愿提供的信息、负责人、跟进状态、下一次跟进时间。不能确定来源时保持未知。

标准状态：待确认 -> 已分配 -> 跟进中 -> 有效商机/暂不匹配/已关闭。可轻量同步既有CRM，不承担成交订单全流程。

### GEO的最小保留能力

固定少量真实采购问题，定期保留原始AI回答、品牌提及、引用来源和采集条件；生成下一轮内容建议。API、消费者界面与人工样本分列。采样平台数量和次数受预算控制。

这保证GEO定位有可观测依据，同时避免首版变成全功能监测产品。普通内容分发不能承诺必然带来AI推荐；客资的真实来源与GEO观察分别展示。

### 首版交付边界

七个业务目标AI平台及12个自媒体保留为覆盖路线图，先验证每个客户实际需要的少量渠道。至少跑通一种图文发布路径、一种视频发布路径（可用客户已有素材）、一个真实客资入口和一次固定问题复测。

首版只需证明：企业给资料 -> 生成有事实依据的内容 -> 人工批准 -> 发到指定账号 -> 收集真实咨询 -> 分配和提醒跟进。每一步留下版本和执行证据。

### 对已有文档的适用说明

前期集成方案V1及制造业蓝图中的独立SEO、媒介采购与复杂分析功能转为后续可选范围；不再是首版必建项。用户若希望客资还包括其他含义，再扩展此处定义，不直接扩大监控或采集权限。
