WorkFX product-framework study on 2026-10-02, using an authenticated free-tier brand workspace plus official documentation inspected in the prior turn. The live workspace, saved brand profile, visibility summary, generated content cards and preview canvas were observed; most module entries showed trial-gated feature previews rather than usable full pages. ## 研究对象与证据边界

用户“这个”指上一条明确给出的WorkFX链接；浏览器当前Trendee页面只是环境信息，没有被当成替代目标。

2026-10-02实际查看：已登录WorkFX品牌工作空间，左侧导航、现有品牌DNA、现有可见度结果、生成博客及社媒内容卡片，打开博客预览后出现右侧画布。

点击智库问答、内容排期、营销矩阵和内容助手入口时，当前免费账号显示功能介绍和开启7天试用入口。没有激活试用、生成新内容、修改品牌资料、发布文章或绑定新账号。

因此下文分别区分：实际工作空间观察、试用引导/官方文档描述、我们的实现建议。没有检查其服务端、数据库或Agent实现。

## 1. 可见导航框架

| 分组 | 工作空间中可见入口 |
|---|---|
| 品牌上下文 | 品牌切换 |
| 总览 | Workspace、内容排期 |
| 操作中心 | 内容创作；内容助手下有用户意图、用户问题、内容生成；Reddit、Instagram & Facebook、产品列表、技术诊断 |
| HUB | 智库问答、品牌基因、营销矩阵、资产 |
| 公共控制 | 积分、套餐、个人中心、邀请、语言、文档、Lumi助手 |

值得借鉴的是分工：HUB保存共享上下文，操作中心完成专业任务，Workspace串起跨模块行动，排期承接生成结果。

## 2. 产品工作流

基于实际Workspace及已读官方文档：

企业资料与网站 -> 可编辑品牌定位/受众/语气 -> 关键词与用户意图 -> 用户问题 -> 内容生成 -> 预览/编辑 -> 排期/发布 -> 可见度及流量反馈。

当前Workspace将品牌DNA、AI可见度和内容卡片放进一条会话；内容卡片可直接预览，右侧画布显示正文。这使策略与具体产出可以在同一页面检查。

营销矩阵的官方定义是各平台的角色、语气和素材要求，不等于平台账号已经授权，也不等于该平台全部内容类型可自动发布。

排期引导展示月历/周历/列表和待确认/可发布等示意，未在当前账号完成真实排期操作。

## 3. 可复用的六项设计

| 设计 | WorkFX证据 | 我们如何采用 |
|---|---|---|
| 品牌/项目统一上下文 | 顶部品牌切换、共享品牌DNA | 企业切换后，知识、内容、账号、客资共同切换并保持租户隔离 |
| 对话加产物画布 | 实际打开博客预览后的左右分栏 | 左侧提出任务/修改要求，右侧审阅稿件、来源和版本 |
| 先确认定位再生成 | Workspace引导确认品牌与策略，官方Brand Hub流程 | 增加产品参数、工况、资质与技术核准，不让草拟定位直接成为事实 |
| 意图到问题再到内容 | 实际导航和Content Assistant文档 | 简化为内容创作中的三步流程，问题标注真实来源或AI建议 |
| 一个主稿形成平台版本 | Workspace已有不同平台内容卡片，官方内容文档 | 保存主稿与派生关系，各渠道使用不同格式而非重新编造事实 |
| 内容连到日历和表现 | 排期入口、Performance文档 | 审核通过后进入分发日历，再关联可获取的内容表现和客资 |

## 4. 制造业场景需要修正的设计

### 4.1 品牌摘要先核准

当前样本的品牌定位包含“工业景观设计”，并把它写进现有博客。这是否属于该企业实际业务，本次没有独立验证。我们应显示原始依据和待确认标识；不能因为摘要已保存就把推断升级为确定事实。

### 4.2 技术承诺需证据与条件

当前样本文案出现“彻底解决”“确保盐雾测试稳定达标”“轻松通过表面处理环评”。本次预览没有展示对应测试条件或来源。这不是对企业真实能力的否定，而是生成稿发布前需要验证的内容。

我们的内容画布应提供事实依据栏：对应型号、工况、测试方法、出处和核准状态。关键结论不能只依赖文风调整。

### 4.3 可见度结果需解释范围

当前Workspace展示0.0%与若干英文问题、ChatGPT/Claude/Gemini的结果。该值仅是页面报告值；未核验采集渠道、时间、完整样本与重复次数，不能推断为品牌在所有AI中没有曝光。

我们的概览应一起显示：有效样本数、问题版本、语言/地区、采集方式、时间、失败数和原始回答入口。未知或未测与明确未提及分开。

### 4.4 国内市场不能直接套海外渠道

保留统一营销矩阵概念，执行渠道按客户实际需要配置。国内12个平台与官网连接发布适配层；不能把Reddit/Instagram等入口照搬为制造业首版必备栏目。

### 4.5 客资中心需自行补齐

本次可见导航和已读文档没有充分证据证明其具备我们所需的完整客资收集、去重、分配和跟进工作流。这只是当前研究范围的缺口，不是声称产品绝无此能力。

我们保留独立客资中心，接授权咨询、官网表单与导入；区分内容表现、AI引用和真实销售线索。

## 5. 对我们平台的框架建议

保持 [[2026-10-01-GEO-six-modules-product-review#12. 最新定位下的精简方案：四个业务板块与轻量工作台|精简方案]] 的四个业务板块，不因借鉴WorkFX重新扩大范围。

```text
企业/项目切换
工作台
  今日任务、待审核、待发布、待跟进、简要GEO与内容表现
企业知识库
  企业/产品事实、资料、FAQ、素材、核准与版本
AI内容创作
  选题与采购问题 -> Skill生成 -> 画布编辑与技术审核
矩阵分发
  渠道策略、授权账号、发布日历、发布记录与异常
客资中心
  咨询收件箱、需求标签、分配跟进、回复草稿、导出
设置
  团队权限、渠道连接、额度费用、日志
```

知识库中的“渠道表达配置”供内容调用，发布账号授权由矩阵分发管理。网站SEO只保留内容检查和CMS投递，付费媒介先用轻量资源与交付记录。

工作台可用自然语言发起任务，但结果必须落成可管理对象：知识核准单、内容草稿、发布任务或客资跟进。不能让所有业务只存在聊天历史里。

内容编辑页：左侧任务/改写对话，中间主稿与平台预览，右侧可折叠的事实来源和核准信息；小屏可用标签切换。此为我们的设计建议，并非WorkFX已观察到的三栏实现。

## 6. 实现建议，不是对WorkFX内部的推断

- 公共业务对象：企业、产品、核准事实、问题、内容版本、平台变体、发布任务、咨询、跟进。
- 智能体按明确权限调用检索、生成、校验、适配、发布状态查询和客资分类工具；发布与触达遵循客户授权和核准版本。
- 每项异步任务保存阶段、结果、费用和失败原因，刷新页面仍能继续查看。
- 交互上的对话助手可以统一，数据与权限依旧按模块明确管理。
- 不需要复制WorkFX的代码或商业素材，采用独立实现的产品组织方式即可。

## 7. 下一步界面设计的最小范围

优先设计五张页面：工作台、企业知识库、内容创作画布、分发日历、客资收件箱。用一条产品资料到咨询跟进的样例串联交互，再决定详细组件与接口。

进一步试用待用户选择是否开通模块；本次完成的是可见产品框架与交互分析，不是全模块功能验收。
