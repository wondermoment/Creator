## For future Claude
Manufacturing B2B GEO delivery blueprint recorded on 2026-10-01. The user explicitly chose a general delivery foundation before specializing by industry, covering China and overseas AI discovery, knowledge-backed content skills, social publishing and paid media packages. Vendor capabilities below were checked against public documentation, not production-tested; package scopes and architecture are recommendations, not purchased services or vendor quotations.

## 已确认范围

用户要求：制造业实体企业，面向 B2B 品牌影响力与产品内容布局；覆盖豆包、腾讯元宝、Kimi、DeepSeek、ChatGPT、Claude Code、Grok；内容生产采用知识库和 Skill 智能体，连接自媒体发布和可付费的媒介组合。用户进一步确认：暂不限定行业，先做通用交付底座。

相关前期选型见 [[2026-10-01-GEO-enterprise-delivery]]。

本方案是产品与交付设计，没有注册账号、向外发布、购买媒体、接入客户资料或部署系统。

## 产品定位

建议名称：制造业 B2B 品牌与产品内容交付平台。

价值主张：把企业产品与技术资料沉淀为可核实的知识资产，形成面向采购和工程师的内容，分发至自有网站、行业渠道和自媒体，再以 AI 回答、引用与询盘数据持续复盘。

系统分别管理内容、发布、AI 观测、业务线索。公开发布并不等于搜索引擎收录，收录也不等于被 AI 引用；各状态应保留独立证据。

### AI 平台边界

- 豆包、元宝、Kimi、DeepSeek、ChatGPT、Grok：按消费者产品、地区、语言、联网模式分别观察；供应商模型 API 是另一条观测渠道。
- 企业内容布局主要通过公开官网、技术资料、第三方报道及可访问内容实现，不承诺统一的“品牌入驻 AI 排名”通道。
- Claude 聊天产品可以列入品牌问答观察；用户明确提到的 Claude Code 保留为独立技术触达方向。
- Claude Code 对工业软件、API、SDK、设备接入文档、示例代码与 MCP 工具可能有价值；普通工业品先做好公开产品页、选型资料和技术手册，不强行为每家客户制作 MCP。
- 不把 Kimi API 等同 Kimi 网页搜索，不把 DeepSeek API 等同 DeepSeek App，不把腾讯模型接口直接标成元宝真实界面数据。

## 通用底座与行业配置

通用对象：租户、成员、品牌、产品、知识来源、事实、问题集、Skill 版本、内容版本、审批、渠道账号、发布任务、发布 URL、AI 采样、引用、媒介订单、询盘。

行业配置包通过版本化配置扩展：

| 配置 | 示例 |
|---|---|
| 产品字段模板 | 设备的产能/精度/功率；材料的牌号/工况/测试方法；元器件的封装/接口/温度范围 |
| 术语和单位 | 中英名称、缩写、单位转换、禁用错误译法 |
| 采购角色 | 采购、工程师、技术负责人、工厂负责人、渠道商 |
| 选题模板 | 原理、选型、应用、对比、安装、维护、故障、交付、总拥有成本 |
| 事实校验规则 | 参数不能脱离测试条件；认证必须绑定范围和有效期；案例结果不得跨工况外推 |
| 渠道与媒体池 | 按行业、国家、语言、目标职位和内容形式配置 |

首版只提供“通用工业 B2B”配置包。采用核心关系字段加扩展字段 schema，避免为每个行业开发一套系统。

## 知识库

必须同时支持结构化产品库与文档检索。向量检索用于寻找证据，产品参数和单位应保留在可验证的结构化字段中。

| 知识类别 | 必备内容 |
|---|---|
| 企业与品牌 | 法定名称、品牌、地区、工厂、服务范围、授权公开的资质 |
| 产品与型号 | 系列/型号、参数、单位、适用与不适用工况、接口、交期表达规则 |
| 技术与应用 | 操作手册、选型方法、维护、故障、解决方案 |
| 案例与证据 | 场景、前提、实施、测量方法、结果、客户公开授权 |
| 商务问答 | 起订量、定制范围、售后、交付和认证问题 |
| 媒体素材 | 图片、视频、图纸、来源、使用授权、可公开版本 |
| 双语术语 | 品牌及型号固定译法、产品术语、单位、地区表达 |

每条事实记录：tenant_id、product_id、source_id、文件版本、页码/表格/原文片段、fact_id、值与单位、工况、适用范围、有效期、公开级别、核准人。

资料等级：公开、内部、限制传播。公开内容生成只能引用当前用户和目标渠道允许使用的资料；内部报价、未发布产品和客户图纸不得自动流入外发内容。发生证据冲突时生成待确认任务，不让模型自行择一编造。

## Skill 与智能体工作流

Skill 是带输入、输出、规则和验收的可版本化任务包；Agent 负责依照状态调用 Skill 和工具。租户知识在知识库中，行业规则在配置包中，通用 Skill 不复制每家客户的资料。

| Skill | 输入 | 输出与验收 |
|---|---|---|
| 产品资料整理 | 手册、表格、访谈记录 | 产品卡与待确认字段；关键参数附来源 |
| 采购问题规划 | 产品、目标角色、销售 FAQ | 按采购阶段和语言分类的问题集 |
| 证据检索 | 选题、产品、受众 | 证据包和信息缺口；限制跨型号引用 |
| 技术内容写作 | 证据包、模板 | 主稿与 claim-to-fact 对照 |
| 事实与技术审核 | 主稿、来源 | 参数/单位/认证/案例核验，待确认项 |
| 双语本地化 | 已核准主稿、术语表 | 目标语言版本；型号、单位和工况检查 |
| 渠道改编 | 已核准内容、渠道规格 | 标题、正文、封面建议、摘要、脚本 |
| 发布执行 | 已批准版本、账号、排期 | 平台任务 ID、状态、URL 与失败原因 |
| GEO 复测 | 固定问题集、配置 | 原始回答、提及、推荐、引用和采样条件 |
| 客户报告 | 交付、监测、线索记录 | 执行成果、观察变化、问题和下一步 |

建议统一 JSON 契约，至少包含 tenant_id、product_id、language、fact_ids、source_version、skill_version、claims、review_status、target_channels。

工作流先做显式状态机：检索 -> 写作 -> 校验 -> 技术审核 -> 渠道适配 -> 审批 -> 排期 -> 发布 -> 回执 -> 复测。关键参数使用确定性校验；LLM 自评不能代替证据和工程师审核。

## 内容布局

建议围绕采购决策建立主题组，而不是只按平台写稿：

1. 品类是什么、适合什么工况。
2. 怎么选型号、哪些参数真正重要。
3. 与其他技术路线或材料相比有何取舍。
4. 安装、维护、故障和兼容问题。
5. 应用案例、测量方法、成本与交付能力。

一份已核准技术主稿可派生：官网产品/应用页面、知乎选型回答、公众号深度文、行业投稿、英文应用笔记、LinkedIn 摘要、视频脚本。派生数量单独统计，不能当成同样数量的原创研究内容。

优先补中英文官网、HTML 产品页、参数表、FAQ、应用案例和联系入口。技术 PDF 保留下载，同时提供可访问的网页摘要与关键参数。引用与询盘优先落到长期可维护的自有页面。

### 自动发布设计

- 有正式接口的渠道用 API；其余通过独立发布 worker 或授权登录的浏览器执行器。验证码/登录过期进入人工接管，不假报成功。
- 对客户授权且已审核的内容支持定时自动发布；权限配置按客户、平台、内容类型和预算范围保存。
- 状态：待审核、已批准、已排期、执行中、草稿已同步、平台审核中、公开发布、失败、待人工处理、已撤回。
- 保存账号标识、内容版本、任务 ID、URL、时间、平台回执；需要时保存截图。用幂等键与查询防止超时重试造成重复发文。
- 草稿完成不能标为发布完成；平台提交成功不能标为公开可访问；发布成功不能标为 AI 引用成功。

| AI 监测 | [Elmo](https://github.com/elmohq/elmo)、[OpenGEO](https://github.com/cangqiaoGEO/opengeo-platform)，MIT | 国际监测底座与中文/Studio 参考；Kimi 和消费者界面覆盖另验 |
| Skill 内容流水线 | [IP Publisher](https://github.com/veeicwgy/ip-publisher)，README 标 MIT | 参考知识库、审核报告、发布包契约；不是完整 SaaS，默认不直接发布 |
| 国内图文 | [Wechatsync](https://github.com/wechatsync/Wechatsync)，GPL-3.0 | 浏览器插件/CLI/MCP，优先作为独立工具接入；分发修改版需履行许可义务 |
| 国内视频 | [social-auto-upload](https://github.com/dreammis/social-auto-upload)，MIT | 上传与定时候选；平台版本和账号实测决定可用性 |
| 海外发布 | [Postiz](https://github.com/gitroomhq/postiz-app)，AGPL-3.0 | 采购托管服务或按许可部署；修改并对外提供网络服务涉及源码义务 |
| 可视化编排备选 | [Dify](https://github.com/langgenius/dify/blob/main/LICENSE) | 许可带多租户和前端标识限制；多客户 SaaS 不能按无条件 Apache-2.0 使用 |

这些组件并非即插即用。自研统一的租户、产品事实、内容版本、审批、发布任务、媒介订单和报告对象，用接口连接组件，避免把多个完整后台直接拼在一起。按实际依赖版本复核许可；独立进程并不自动解决所有许可问题。

建议技术边界：统一 Web 管理端 + 业务 API + PostgreSQL + 对象存储 + durable job queue + 检索服务 + 隔离发布执行器。已有团队技术栈优先；不必首版同时引入多个向量库与图数据库。

## 付费媒介组合

先建设可配置媒介池，不预设某平台一定被某 AI 引用。按客户固定问题集里实际出现的来源、受众相关性、编辑质量和业务效果筛选。

### 渠道候选与证据边界

- [工控网](https://www.gongkong.com/)：2026-10-01 页面可见自动化、设备、应用案例、厂商品牌等内容；适合工业控制相关客户，具体付费资源、发布条件和价格待询价。
- [OFweek](https://www.ofweek.com/)：行业频道候选，细分领域和商业权益待核查；本次直接抓取有编码问题，不据此确认具体套餐。
- [美通社 PR Newswire](https://www.prnasia.com/)：2026-10-01 官方页面可核实新闻稿发布、制造业分类和跨地区传播；适合新品、认证、展会和重要合作。付费分发不能表述成独立媒体背书。
- [Thomas](https://business.thomasnet.com/)：2026-10-01 官方页面明确工业供应商资料及 Sponsored Listings；适合北美工业采购触达，客户资格、国家覆盖与报价待确认。
- GlobalSpec、DirectIndustry：候选池保留，本次官网访问返回 403，未核实当前商业套餐，不列为已验证可购买项。

### 三种可配置采购包

| 组合 | 构成建议 | 验收重点 |
|---|---|---|
| 国内技术影响力包 | 1 个匹配行业渠道的深度应用内容/技术合作 + 2 个相关垂直内容合作 + 自媒体适配分发 | 真实版位、内容形式、公开 URL、存续期、阅读/点击报告、询盘归因 |
| 出海品牌与采购触达包 | 英文官网内容 + 匹配地区的新闻稿传播 + 工业采购目录/赞助展示 + LinkedIn/YouTube 内容 | 地域和受众、落地页、有效会话、下载/询盘；分别核算目录、媒体与广告 |
| 展会/新品专项包 | 展前技术预热 + 新品技术稿 + 展会/行业媒体合作 + 演示视频 + 展后案例与销售跟进 | 内容、场次/版位、发布时间、名单取得方式、询盘及跟进 |

以上是采购结构建议，并非供应商已售套餐或价格承诺。每单按预算给 2-3 个可替换方案；媒体费、内容制作费、代运营费和税费分列。

媒介 SKU 字段：供应商、行业、国家、语言、受众职位、站点/版位、形式、是否付费标识、编辑权、外链规则、站点可访问性、预计留存、价格/币种/有效期、交期、退款/补发、证据要求。

采购流：需求 -> 候选组合 -> 有效报价 -> 客户批准 -> 下单 -> 审稿 -> 发布 -> URL/版位核验 -> 效果记录 -> 结算。系统可以管理和生成订单，不在客户未批准前自动付费。

优先花钱获得相关受众、专业内容或有价值的分发，不购买虚构测评、伪造专家评价或保证 AI 排名。新闻转载覆盖数与独立原创报道数分别统计。

## 标准交付产品

建议把商业交付拆为一次性建库启动 + 按月运营 + 按单媒体采购，不把所有成本塞入发文数量。

| 阶段 | 建议交付范围，需根据客户资料量调整 |
|---|---|
| 启动 | 企业档案、首批产品事实库、中英术语、账号/权限检查、问题基线、90 天内容计划 |
| 月度内容 | 固定数量的技术主稿、产品/应用页、FAQ、平台派生稿和视频脚本；审核记录 |
| 月度监测 | 固定问题集、选定平台与渠道采样、引用分析、失败率、优化任务 |
| 月度报告 | 已交付内容、公开发布、发现/引用证据、业务询盘与下月计划 |
| 媒体专项 | 独立预算、渠道与版位清单、客户批准、发布凭证、效果与结算 |

合同可承诺执行范围、响应时效、合格内容数量和采样覆盖；AI 推荐和自然流量增长作为观察目标，不承诺稳定排名。

## MVP 与验收

P0：多租户/角色、产品事实库、通用 Skill 工作流、审核/内容版本、官网和 2-3 个国内图文渠道、发布状态与 URL 回收、国内和海外各一条可验证监测路径、人工采样导入、客户报告、媒介清单/报价单。

P1：扩到用户列出的全部目标 AI 平台和渠道、海外发布、视频上传、媒介采购管理、成本/额度、CRM 线索。

P2：行业模板市场、多语种规模化、跨客户匿名基准、实验与效果归因。

试点建议：3 家企业，每家先选 1 个产品系列；知识覆盖、平台配额与采样预算明确后，再展开内容数量。优先证明从资料到合格内容、从内容到公开 URL、从 URL 到可复查复测的完整链路。

必须验证：

1. 两个客户之间的产品、文档、账号和报告严格隔离。
2. 参数、单位、认证和案例结果可回到原文件定位。
3. 登录过期、平台审核、失败与超时状态正确；重复执行不重复发文。
4. 只有核准内容版本可以发布，修改正文后重新进入审核。
5. API 与消费者界面采样分开，失败不算未提及，样本和问题版本可追溯。
6. 报告每个数字能定位原始证据；媒体订单有批准预算和发布凭证。

## 指标

- 生产：资料覆盖、证据关联率、技术审核通过率、每篇成本与人工时间。
- 发布：草稿成功、提交成功、公开发布、有效 URL、内容留存各自统计。
- AI：品牌提及、明确推荐、自有域引用、第三方品牌引用、品牌事实准确性，按问题/语言/渠道/时间查看。
- 业务：产品页有效访问、资料下载、询盘、样品申请、报价请求、CRM 阶段；制造业销售周期长，早期询盘不能直接等同收入。
- 成本：模型、搜索/采样、抓取、存储、人工审核、内容制作、媒体采购分别计账。
