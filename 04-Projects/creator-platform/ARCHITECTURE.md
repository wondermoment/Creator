## 一、我们要造什么

Palantir 用了 20 年证明一件事：**把企业经营现实做成可计算的业务图谱，再用 AI 在图谱上推理和执行，这就是未来的操作系统。**

Creator 的起点不是「做一个 Palantir 中国版」，而是在 AI 原生时代**重新造这个东西**：

- Palantir 的 Ontology 靠 FDE 手工建，我们的 Ontology 由 AI 辅助自动生成
- Palantir 面向 Fortune 500 和政府，我们从 10 万/年的中等企业开始
- Palantir 没有中国生态集成，我们原生对接微信/企微/飞书/抖音/小红书
- Palantir 的模板孤立在每个客户内部，我们的模板跨客户学习、公开交易
- Palantir 的 FDE 是纯人工，我们的 FDE 由 AI Agent 深度辅助

## 三、为什么能比 Palantir 更牛

### 3.1 模板飞轮（Template Flywheel）

```
FDE 进场建 Ontology
       ↓
跑通第一个客户（长寿诊所 A）
       ↓
沉淀为「长寿诊所模板 v1」
       ↓
第二个客户（医美机构 B）直接 fork 模板
部署时间：从 6 周 → 2 周
       ↓
每个新客户都让模板更精准
边际成本趋近于零，利润率趋近于 100%
```

### 3.2 AI 原生 FDE

Palantir 的 FDE 是人工成本中心。Creator 的 FDE 是：
- AI 自动扫描客户数据 → 提议 Ontology 草稿
- FDE 审核和调整（从 0 建 → 从 80 分改到 100 分）
- AI Agent 自动完成数据清洗和字段映射

FDE 人效提升 5-10x，同样人数可以服务 5-10x 的客户。

### 3.3 中国生态原生

| 数据源 | Palantir | Creator |
|--------|----------|---------|
| 企业微信 | ❌ | ✅ 原生 API |
| 飞书 | ❌ | ✅ 原生 Webhook |
| 抖音/小红书线索 | ❌ | ✅ |
| 微信支付订单 | ❌ | ✅ |
| 私域运营数据 | ❌ | ✅ |

### 3.4 从内容到经营的完整链路

Palantir 理解「企业内部数据」，不理解「内容→私域→成交」这条中国特色链路。

Creator 的 Ontology 原生包含：
- ContentAsset（内容资产）→ 带来哪些联系人
- Contact（联系人）→ 从哪个平台进入私域
- PrivateDomainJourney（私域旅程）→ 从粉丝到付费客户的全过程

## 四、第一垂类：长寿诊所·智能健管·经营决策中枢

### 核心业务对象（Ontology Objects）

```
ContentAsset ──产出线索──→ Contact ──进私域──→ Lead
                                                 │
                               ┌─────────────────┘
                               ↓
                           健康档案 (HealthProfile)
                           咨询记录 (Consultation)
                           意向评分 (AI: IntentScore)
                               │
                               ↓
                           Customer（付费客户）
                           ├─ 健管方案 (HealthPlan)
                           ├─ 订单 (Order)
                           └─ 跟进任务 (FollowUpTask)
```

### AI Agents（第一期三个）

1. **高意向识别 Agent** — 扫描所有 Lead，输出意向评分 + 建议动作
2. **流失预警 Agent** — 监测活跃客户的沉默信号，提前预警
3. **复购推荐 Agent** — 在订阅即将到期或健康目标达成时推送升单建议

## 五、技术栈

| 层次 | 技术选型 | 原因 |
|------|----------|------|
| Backend | Python FastAPI (async) | AI 生态最全 |
| 数据库 | PostgreSQL + pgvector | 关系 + 向量一体 |
| 缓存/队列 | Redis | 事件流 + 任务队列 |
| AI | Claude API (Anthropic) | Tool Use 结构化输出稳定 |
| Frontend | Next.js 14 + shadcn/ui | 快速，组件生态好 |
| 图可视化 | React Flow | Ontology 图可视化 |
| 容器 | Docker Compose → K8s | 本地 → 云 |
