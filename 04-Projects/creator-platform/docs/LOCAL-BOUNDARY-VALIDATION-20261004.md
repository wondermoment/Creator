# 本地访问边界验证 · 2026-10-04

## 问题与修复
主应用的 overview、客户详情、健康记录、复核等接口没有应用 commerce 等路由已有的 local_only 检查。虽然启动命令绑定127.0.0.1，仍不应仅依赖监听地址。

现对 FastAPI 应用全部普通路由使用共同依赖：检查直接客户端为 loopback、Host 为 localhost/loopback、Origin 与本机服务同源；额外拒绝 Sec-Fetch-Site: cross-site。错误文案改为本地演示，覆盖范围不再仅描述交易沙盒。静态资源与框架自动文档不等同于受此依赖保护的 API；其中不存放用户数据。

## 验证
37 项后端测试通过。新测试使用临时数据库与合成 ASGI 请求，覆盖外部来源 IP、伪造 Host、跨域 Origin、null Origin、cross-site 请求头，对客户读取、复核写入、课程、商城与模型入口验证403。拒绝路径用数据库访问断言确保未读数据。合法同源 loopback 的首页与 overview 成功；原健康工作流仍通过。

测试框架版本不支持 TestClient(client=...)，因此使用仅在测试中设置连接来源的 ASGI 包装器；未在生产代码加入 testclient 白名单。首次测试错误已修正后重跑全部套件。

## 限制与上线阻塞
本轮没有尝试重启：沿用上一轮审批拒绝后待授权的状态。修复只在源码/隔离测试进程生效，不能宣称运行中服务已加载。
本机限制不是账号认证、角色权限或租户隔离。反向代理若修改 Host/Origin 或转发头，不得为了上线删除限制；应先完成正式认证与授权设计。服务启动应继续绑定 loopback，代理转发头信任需单独审计。
