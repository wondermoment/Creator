# 咨询提交和后台进度保存的等待恢复

日期：2026-10-05。承接上一轮咨询列表GET恢复，本轮处理serviceInquiry POST与inquiryFollow PATCH。小乔原生四姿势、10/25检测图已完成，不重复生成。

## 发现与修改

原POST/PATCH直接等待api，没有上限；网络请求不结束时共享表单永久禁用。返回缺失字段也被当作保存成功。源码已有POST request_key幂等、PATCH expected_version并发保护，本轮保留这些语义，没有改后台。

新增inquiryWrite：30秒客户端等待上限，AbortSignal，验证POST返回非空id和合法status、PATCH返回ok=true。网络错误、超时、异常响应均保守提示“未能确认保存结果，服务端可能已处理”，不假称保存失败或服务端取消。不自动重试。

咨询POST：首次发送后保留原请求标识与内容，手动重试必须完全一致；改变内容后阻止再次请求，提示先关闭并刷新核对。空白需求发送前拒绝。请求标识只在当前窗口内保存，关闭/刷新页面后不持久保存，跨窗口重复创建风险未完全解决；不得称全局exactly-once。

后台PATCH：发送前去除进度说明首尾空白并拒绝空值；任何未确认结果后，同一窗口再次保存只提示核对，不追加请求。同时列表进入“结果待核对”状态；须关闭、刷新并重新打开，使用当前timeline版本。该操作仍依赖服务端expected_version，并不代替正式权限或服务端生命周期管理。

已确认写入后才刷新列表并触发表单成功；列表刷新失败仍按上一轮规则显示旧记录可能过期。写入已确认与列表刷新状态分开。共享表单既有代次保护保留，迟到结果不能关闭后开的窗口或显示虚假成功。
