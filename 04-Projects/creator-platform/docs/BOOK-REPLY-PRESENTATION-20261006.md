# 书籍回复排版与等待反馈 · 2026-10-06

用户要求去掉回复中的Markdown符号、清晰分段并局部加粗；点击发送后问题应出现在对话中，等待需要有过程反馈。

## 完成的界面行为

- 书籍助手回复用受限Markdown渲染：`#`标题转为小标题，`**`强调转为局部加粗，有序/无序列表转为列表，空行转段落；空行不重置连续有序列表。
- 回复有独立正文容器、行距、段距、标题间距与低饱和重点颜色。用户问题仍为转义原文。数学乘号、C#与引用编号等普通内容不一刀切删除。
- 原始HTML总是转义，不开启模型提供的HTML、脚本或任意链接。这不是完整Markdown实现（例如表格并未支持）。
- 点击发送立即在聊天区显示问题、清空输入框，显示动态圆点及真实经过秒数；20秒后提示等待较久。显示的是等待状态，不是假进度百分比或伪称模型已完成的分析阶段。
- 成功后替换等待卡片；失败恢复原问题到输入框并保留先前对话。超时、迟到结果与切书隔离仍保留，计时器会清理。未做真正流式输出，也不把视觉等待提示当作后端提速。
