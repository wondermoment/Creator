# API 敏感响应缓存 · 2026-10-04

## 问题
客户详情、健康记录、书籍历史及报告附件没有统一禁缓存响应头。商品图单独设置 no-store，不能覆盖其他敏感响应。

## 修复
API 响应统一添加 Cache-Control: no-store, private、Pragma: no-cache、X-Content-Type-Options: nosniff。仅处理 /api 及 /api/ 路径，保留静态资源原有行为；附件仍以 attachment 返回。覆盖正常响应及框架处理的403/404/422错误。

## 验证
46 项后端测试全部通过。新测试使用临时数据库/临时书籍目录，检查overview、客户详情、空书籍历史及错误响应；上传合成签名文件后检查报告下载内容未改变、attachment仍在且禁止缓存；静态JS可访问。不接触现有用户数据，不调用模型，不发布部署。

## 限制
no-store是缓存指令，不会清理此前缓存、localStorage、用户主动下载的文件或截图，也不替代身份授权、加密或数据删除。未验证所有浏览器的历史恢复行为。未捕获异常产生的500响应、代理缓存配置需另行验证。
运行服务未重启，源码通过隔离测试但尚未确认运行实例加载；沿用已有重启审批阻塞，不反复尝试。
