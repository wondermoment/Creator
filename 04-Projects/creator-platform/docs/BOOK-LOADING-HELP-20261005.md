## 问题与修改

独立 openReadingChat 未带共享教练的本地急症指引；初始化 history GET 和 source status GET 没有超时，历史请求不返回时，发送按钮会一直禁用。

- 首屏加入已有 coachUrgentHelp，置于可变 reading-log 外。展开指引无需发送问题、同意云模型或等待后台；说明中国大陆120与其他地区当地急救号码。仅显示指引，不自动识别症状、拨号或派车。
- 新 readingLoad：每项只读 GET 15秒等待上限，Promise.race + AbortController，成功/失败都清理计时器。两项仍顺序读取，最坏等待不超过约30秒，不是模型生成超时。
- 失败显示“重新加载”，不自动重试；保留当前输入草稿。历史失败时不启用发送，避免把未取到的历史误当空历史。状态失败后重试不重复覆盖已取到历史。原模型未配置禁用逻辑保留。
- 读取期间禁止重复加载和上传；迟到响应、切换另一书籍后的旧加载均不覆盖当前窗口。
- 360×640 实测发现初版展开指引挤出发送区，修为指引高度最多24dvh且内部可滚动，fields允许纵向滚动作为短屏兜底。最终 fields scrollHeight/clientHeight 均563；发送按钮底部622，小于视口640；指引 scrollWidth/clientWidth 均328，无横向溢出。
