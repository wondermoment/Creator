# 商品列表读取异常恢复

2026-10-06。先读最新交接与主图恢复记录，不重复图像、模型或库存测试。具体缺陷：catalog读取无等待上限、并行读取没有旧响应隔离、未知JSON直接进入渲染；首次加载失败仍显示“还没有自建商品”，前台无重试入口。

## 完成

loadManagedProducts新增15秒独立截止、AbortController与请求序号；新读取终止旧等待，即使底层忽略中止也不能让旧结果覆盖新列表。确认结构完整后才替换列表，检查编号唯一、文本类型、有效状态、价格库存整数、图片标记和revision格式。失败/超时保留最后一次有效列表，清理计时器，显示错误与旧数据提示。

后台商品工作台有“刷新商品”按钮，只有成功读取空数组时显示空列表说明；加载中/失败时编辑和上传入口禁用。前台自建商品区域在读取中/失败时提供状态与重试。已有商品预览仍可读；前台库存和成交条件仍由后端下单检查，未新增实时订阅。静态脚本版本catalog-recovery-6。

## 验证

新增product-catalog-recovery检查覆盖：旧成功迟到、新请求替代中止、永久挂起超时、超时后迟到响应、7类异常数据、旧列表保留、状态/按钮/空态、重试成功与首次失败。product-image-recovery / product-revision / product-id-escaping / form-async回归通过，共5套；JS语法通过。

首次回归中product-image-recovery在成功上传后断言“零计时器”失败：新实现启动catalog自己的15秒计时器。更新为先验证上传已完成、只有列表计时器仍在，再触发模拟截止并核对清理，复测通过。没有删除上传成功不依赖catalog的断言。

真实浏览器独立测试标签打开#commerce，点击“刷新商品”后恢复可用，空列表说明正确，无错误状态，新脚本版本确认。截图product-catalog-refresh-20261006.png、记录PRODUCT-CATALOG-BROWSER-20261006.json。当前自建商品为空；浏览器未验收非空/故障网络场景，其证据仅为合成DOM与传输检查，不作全流程性能保证。测试标签已关闭，未刷新用户标签或改草稿。

本轮仅前端改动，无后台重启、数据库写入、模型调用、图片生成、付费API、部署、对外消息、真实支付。其他commerce快照与商品保存请求的时限/未知结果处理、图片并发替换、正式身份和对象权限、隐私与商户/医学/素材授权仍是待办；本轮不解除上线条件。
