# 原文问答浏览器取消补齐 · 2026-10-07

## 修复

书籍窗口关闭和替换已经取消公开主题流式请求，但原文路径仍直接调用不接收外部 AbortSignal 的 coachRequest；无流式工具的备用路径也存在相同缺口。结果是旧窗口消失后请求仍等待完成或 270 秒截止。

coachRequest 现在接受可选第三参数 AbortSignal，取消时中止内部传输并独立结束等待；即使底层传输忽略取消也不等待迟到结果。已取消的信号在发送前拒绝，不创建请求或计时器。成功、失败、超时和取消都清理监听及计时器，后续取消不会影响已完成请求。

原文书籍、公开书籍非流式备用、教练非流式备用均传递窗口信号。书籍结束处理另外检查取消状态，避免 formreplace 在旧 DOM 尚未移除时写回旧内容。保持原有超时和未知服务端结果提示。

版本：book-reader sync-cancel-30、coach-chat sync-cancel-16。无后端修改或重启。

## 验证与失败记录

`BOOK-SYNC-CANCEL-CHECKS-20261007.json`：8 套前端回归与两个 JS 语法检查通过。实际 showForm/教练/书籍代码的合成 DOM 测试覆盖 24 种流式、原文、备用路径组合：教练或书籍窗口切换到教练、书籍、普通表单或关闭，旧信号中止，忽略信号的模拟请求仍能结束页面等待，迟到正文/最终结果不串入，新请求和草稿保留，计时器清理。

transport 用例另覆盖已取消信号不发送、成功后移除监听、同步传输异常清理、原 270 秒超时及实际 api/post 向 fetch 传递信号。

首轮新增测试失败为关闭后已打开普通表单却仍执行下一次聊天断言，访问不存在的 nextRequest.signal。修正测试分支后重跑对应套件通过；未因此改变产品逻辑。首轮证据保存在 `BOOK-SYNC-CANCEL-CHECKS-FIRST-20261007.json`，不抹去失败。
