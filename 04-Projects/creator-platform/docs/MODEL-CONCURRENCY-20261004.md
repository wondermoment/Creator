# 本机模型并发保护 · 2026-10-04

问题：各健康教练和书籍问答都通过线程调用本机 Codex，但跨窗口/跨模块没有共享并发限制。多个请求可同时启动模型，造成拥堵和额外套餐消耗。

修改：local_codex.generate 入口添加进程内单槽锁。当前调用未结束时立即拒绝新调用，说明本次未启动模型；不自动重试或后台排队。成功、异常均在 finally 释放。锁在登录检查之前获取，因此重复生成请求也不会触发额外登录检查。

验证：44 项后端测试通过。两项新增隔离测试使用线程事件控制重叠时序，确认第二请求不进入生成函数、第一请求完成后可再次调用、失败后仍可调用。不运行真实模型，不发送健康信息，不修改用户记录。

限制：这是单 Python 进程保护；多 worker/多实例仍需共享队列、每用户限额和预算控制。不能保证子进程超时后所有后代进程退出，也不改变当前约124秒的连接延迟。独立 image_gen 作业不使用此文本生成入口。状态检查接口本身不受此锁限制。

部署状态：源码和隔离测试已完成；未重启服务，运行实例未验证加载。此前审批拒绝重启的阻塞保持记录，不重复请求。上线仍需身份/对象授权、模型端到端验证、后台任务治理与专业签核。
