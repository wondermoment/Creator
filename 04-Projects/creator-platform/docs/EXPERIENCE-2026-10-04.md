# 商品与客服体验改进 · 2026-10-04

## 本轮范围
商品后台支持主图上传、详情预览；前台自建商品详情支持平台咨询和缺货禁用；咨询入库、后台跟进、客户端时间线。均为 loopback 本机原型。

## 设计依据与约束
主方向沿用用户确定的 440px 手机画布、黄色品牌与紫色操作色，不重做主题。
参考：D:/Codex/skills/refero-design/references/craft-details.md 的表单标签、键盘焦点、状态反馈原则。
- 表单保留可见标签；失败时不清空输入，提交中禁止重复点击。
- 主图保持 4:3 展示区，详情 contain 保留商品全貌，缩略图用于后台识别。
- 咨询卡片以状态和主题优先，时间线折叠降低列表长度。
- 按用户要求，咨询由平台接收，不引导到供应商外部预订入口。

## 实现
- product_images 独立表，原内容表无需破坏性迁移。
- 图片内容校验、5MB/2000万像素限制、缩小到1400px、转为JPEG去除元数据。
- service_requests 保存咨询与时间线；请求 UUID 防重复，进度版本防覆盖。
- 待受理需先进入跟进中，才能完成；已完成可重新跟进。
- 本机统一咨询列表，无用户身份隔离，界面已明确标注。
- 旧浏览器草稿保留，可继续填写后提交。

## 验证
- python -m unittest backend.test_shop_experience：8项通过（6项原交易回归 + 2项新增流程测试）。
- 新增测试覆盖重复提交、状态流转、旧版本冲突、非法图片、图片缩放、草稿禁止购买。
- 修改的 JavaScript 文件语法检查通过。
- 实际浏览器：新增草稿 → 预览（缺货禁用）；酒店咨询 → 后台受理 → 我的进度 → 展开时间线，成功。
- 图片上传与返回经过API测试；文件选择器交互未做浏览器上传验收。
- 本轮临时商品和咨询已清理，保留原有业务数据。
- 截图 experience-check-20261004.jpg 为清理前的验收记录。

## 仍需建设
正式账号权限、跨设备隔离、客服通知、正式支付/退款/分账、履约物流；图片管理暂为单主图，不含多图与SKU。
编辑商品库存仍为绝对值更新，生产环境需独立库存调整与版本控制。
