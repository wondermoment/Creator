# 咨询进度读取恢复与旧响应隔离

日期：2026-10-05。本轮选择前台“我的客服咨询与进度”和后台收件箱共用的读取流程。原小乔四姿势、10张新检测图已完成，不重复生成。

## 已证实的问题

原 loadInquiries 没有等待上限和请求代次；首次失败仅写 inquiryError，inquiryCards 仍显示“正在读取咨询记录”。重复刷新/路由进入同时触发GET时，晚到旧响应可覆盖较新记录；返回非数组或不完整时间线还可能使页面渲染失败。均由原实现直接确认，未制造真实服务故障。

## 修改

- 读取GET使用15秒 Promise.race 上限，向 api 传 AbortSignal；即使模拟传输忽略中止也能结束本页等待。中止不等于服务端任务取消。
- 新读取替代旧读取：旧等待立即结束并发出中止，代次检查阻止旧成功/失败改写最新状态。定时器清理，不自动重试。
- loading/error/loaded分开。失败结束加载状态、恢复手动刷新；已有记录保留并标注可能过期。只有成功空数组显示“暂无”，不将错误当空列表。
- 校验数组、必要文字字段、状态和时间线结构，不用坏结果替换上次有效记录。
- 刷新期间或失败后后台跟进按钮禁用；函数入口同样拦截，要求先刷新。并非权限控制；已有服务端expected_version机制未修改。
- customer-service.js缓存版本inquiry-load-8。只改前端GET等待和显示，未改POST/PATCH提交行为。

## 验证

新增 tests/inquiry-loading.cjs：全合成记录/定时器/Promise，覆盖首次失败不再加载、手动恢复到空结果、永久挂起15秒结束、AbortSignal、无自动重试、迟到结果隔离、新请求优先、不完整数据保留旧记录、状态提示、旧记录后台操作拦截、错误HTML转义及离开页面后不重绘。无任何HTTP或用户记录写入。

service-chat、testing-chat-flow回归通过（25×7轮是合成传输测试，不是真实模型175轮）；customer-service JS语法通过。

浏览器正常流程：进入#account读到成功空列表，点击“刷新进度”后仍显示成功空列表且刷新按钮可用。没有新建、提交或更新咨询。截图 inquiry-loading-20261005.png 仅截咨询模块，不包含旁边其他本地记录。异常与乱序场景通过合成测试验证，未在运行服务注入故障。

## 局限

没有新增真实模型调用；最近真实模型127.11秒时延仍未解决。GET恢复不构成权限隔离、医学签核或服务端可靠取消。POST/PATCH提交超时、服务端任务生命周期、用户隔离和专业审核仍需后续验证。未重启服务、对外部署、支付、发外部消息或改变已有用户数据。检测图仍10/25、剩余15项，其余内容待办保留。
