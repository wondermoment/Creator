# 原文问答历史版本提交保护 · 2026-10-07

## 改进

模型已有单进程生成并发限制，但生成结束释放槽位后，到问答历史提交前仍有竞争窗口；其他实例也可能基于相同旧历史生成并追加回复。这样两轮答复都表现为连续对话，后完成的一轮实际却没有看到先提交的新限制。

本轮在SQLite `BEGIN IMMEDIATE`事务内重新读取本书历史，与本次生成所用历史比较，然后才插入问题和回答。历史有变化则409拒绝本轮提交，提示重新打开书籍核对后再提问，不删除先提交的记录，不自动重试模型。

比较包含消息ID、角色、内容、引用及创建时间，不能仅修改相同时间戳内容就绕过；收藏标记不影响模型上下文，因此不触发冲突。其他书籍的记录也不影响本书比较。现有数据库结构不变，无迁移。问题和回答继续同一事务写入，任一插入失败整体回滚。
