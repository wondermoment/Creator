# 自动巡检迭代 03 · 发布回执与排队任务互斥

2026-10-02，自动巡检 geo。沿用现有菜单、数据库与审核流程。

## 复现的问题

已审核内容创建 WordPress 草稿任务后，如果操作员先在外部人工发布并登记回执，旧执行任务仍停留在 queued。原执行器只复查内容版本与审批，没有复查发布记录已变成 recorded，之后仍可能创建多余草稿并覆盖人工回执状态。平台调用处于 running/unknown 时也允许登记人工回执，掩盖了需要核对的执行状态。

用隔离测试数据库复现：人工回执登记返回200，但排队任务未取消；running 状态也错误返回200。未在客户账号调用任何真实平台。

## 修复

- 同一个 SQLite 写事务内登记人工回执并取消该发布记录关联的 queued WordPress 任务，保留取消原因、时间与操作日志。
- 平台任务 running 或 unknown 时返回409，提示先核对执行回执，不覆盖不确定结果。
- 执行器发出请求前再次校验任务状态、发布记录状态和审批版本；取消/已结束/已有回执的任务不能继续提交。
- 不影响已公开文章或历史刊发证据，不把人工回执冒充API发布成功。
