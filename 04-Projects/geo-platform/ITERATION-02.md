# 交付执行层：本轮更新与验收

2026-10-02。本轮沿用现有界面和客户库，没有迁入第三方整套后台。

## 可在现有页面使用

- 工作台/内容中台：企业连接配置、执行状态、费用与 token 记录。提供 OpenAI 兼容模型接口、WordPress、OpenGEO 三类配置。
- 企业知识库：公开 HTTPS 单页导入、基础 PDF 逐页提取、Docling PDF 解析、Crawl4AI HTML 整理。生成待核准知识，保留 URL、原文件、页码、时间和摘要校验值。
- 文档修订：知识升版、重新核准，关联内容撤销审批并标为资料过期。旧内容需要基于最新知识重新生成，不能仅编辑正文绕过源版本检查。已公开文章仍需另行更新。
- 内容创作：可选真实模型或本地资料提纲；真实调用使用 Soul、Skill、企业品牌表达及核准资料快照。后台持久化任务，不在 SQLite 事务中等待外部请求。
- 客户预览：渠道标题、正文、封面、附件、咨询链接分别预览和编辑；修改绑定新版本并重新审核。已审核版本可下载带 SHA-256 的 JSON 发布包。
- 质量检查：编号引用存在性、常见夸大承诺、参数原文匹配、品牌禁用表达；只是规则检查，不能自动证明事实正确。另可导出企业专属 Promptfoo 配置与测试集，不包含密钥。
- 矩阵发布：WordPress 纯文本内容及咨询链接，先建草稿、再显式公开发布。平台回执与人工回执分开；草稿不得计成公开发布。发布时重新提交审批正文，避免远端改稿绕过审批。
- GEO 诊断：模型 API 单题观测单独保存；OpenGEO 只读问题汇总接口按品牌 ID 校验后导入。两者都不自动混入消费者 App 提及率。
- 网站 SEO：官网导入产生单页标题、description、H1、canonical、noindex、图片 alt 检查。不是全站 SEO 审计或搜索引擎收录证明。
- 信源媒介：矩阵发布内记录媒介、选择依据、引用证据、报价日期、人工订单状态与刊发回执，不会自行采购或支付。

## 配置与部署

基础依赖见 requirements.txt。重装解析环境：

```powershell
python -m venv .runtime/parser-env
./.runtime/parser-env/Scripts/python.exe -m pip install -r requirements-parsers.txt
```

锁定环境清单见 requirements-parsers.lock.txt。Docling 模型首次运行会下载，已在此机完成示例所需模型初始化。安装包不代表所有中文扫描件与复杂表格均已通过；需使用客户资料评测。

配置入口：工作台 → 配置连接，或内容创作 → 内容中台 → 配置连接。

- 模型：基础 HTTPS 地址、模型 ID、API key，可选每百万 token 输入/输出价格。费用是配置单价估算，不是供应商账单。云端 GEO 需确认其 API 是否兼容。
- WordPress：官网根地址、用户名、应用密码。创建草稿实际验证写入权限；纯文本及咨询链接可执行，封面/附件暂通过发布包人工交付。
- OpenGEO：已有部署的 `/api/v1` 地址、API key、当前企业品牌 UUID；诊断页填问题 UUID 与日期区间导入。上游当前快照接口只返回汇总，缺少样本分母与完整原始回答，不展示伪造的提及率。

外部端点只支持公开 HTTPS/443；校验解析出的全部 IP，固定 IP 建立 TLS 并保留原域名 SNI，拒绝内网与带凭证重定向。密钥在项目记录中加密，数据库/API/导出不暴露明文；`.runtime/connector.key` 为本机加密主密钥，需与数据库一起安全备份。当前是单机密钥文件方案，非云 KMS。

任务每 2 秒检查，数据库保留任务和结果。服务重启时未完成任务标记未知，不自动重发。WordPress 结果未知要先人工核对；已提供只读核对并按 WordPress 文章 ID 回查状态；不会盲目重发。该执行器只适用于单进程本机服务，尚未完成多进程租约与分布式调度，不要多 worker 部署。
