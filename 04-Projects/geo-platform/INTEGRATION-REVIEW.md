# 品牌铸匠 GEO：现有系统复盘与整合建议

日期：2026-10-02。结论：保留现有客户项目、知识、内容、审批、交付和客资业务底座，暂停扩充一级菜单，优先接通真实生成、可靠分发和效果证据。

本次检查了现有 README 与关键服务端实现，复用了此前 WorkFX 登录观察及产品研究记录，并重新读取了 12 个 GitHub 仓库的 README、许可证元数据、OpenGEO 国内通道代码、IP Publisher 发布包文档以及蚁小二公开 CLI/OEM 页面。没有部署这些候选、调用付费模型、绑定渠道或实际发文；下述优先级是选型建议，不是接入完成声明。

## 1. 自我复盘：什么该保留，什么尚未完成

前几轮推进主要完成界面与业务流程，真实执行能力跟进不足。专家角色、Soul、矩阵和大屏很容易让人误以为自动化已完成；今后必须在相应页面明确显示“人工记录 / 模板生成 / 已连接 / 运行失败”等真实状态。

| 环节 | 当前实际能力 | 下一步价值最高的补齐 |
|---|---|---|
| 客户隔离 | 服务端按项目鉴权、成员角色、资料与文件隔离 | 外部服务、向量检索、缓存、账号凭证、后台任务也继承项目边界 |
| 企业知识库 | 文本、资料核准、品牌基因、关键词查询；PDF 只归档 | PDF/OCR/表格解析、产品事实字段、原始页码、资料失效与冲突处理 |
| 内容创作 | 模板初稿；保存提示词、Skill、Soul、来源与版本 | 真正调用模型，逐条声明引用，主稿派生平台版本 |
| 项目主管 | 规则查询、登记任务、状态跟踪 | 用模型理解需求，受权限约束地调用工具，任务执行结果回流 |
| 审核 | 预览、版本绑定、改稿撤销审批 | 明确审核到各平台最终正文、封面、媒体附件和咨询入口 |
| 分发 | 建立内部任务、人工登记发布 URL | 真实渠道连接、平台回执、异常重试、结果核对 |
| GEO/SEO | 人工 GEO 样本、诊断入口 | 固定问题集真实观测；网站检查产生可执行修复单 |
| 客资 | 联系入口、评论导入、去重转线索、跟进 | 官网表单及获授权的企业微信事件；来源关联与销售结果 |
| 数据大屏 | 展示本地记录并定时刷新 | 展示数据覆盖范围与更新时间，分别统计交付、AI 表现、询盘 |

现有项目隔离、版本门禁、交付去重和审计值得保留。现有测试能证明特定流程行为，不能证明完整安全审计或生产就绪。

蚁小二此次公开页确认存在 CLI 和[开放平台/OEM介绍](https://www.yixiaoer.cn/customized)。仍需取得平台×文章/图文/视频的能力清单、报价、账号隔离方案和实际回执。发布、评论读取、私信读取、回复、统计是不同能力，不能相互推断。

## 3. GitHub：按业务缺口整合

P0＝首条真实交付链所需；P1＝链路稳定后扩展；P2＝按客户需求启用。许可证为本次仓库元数据及声明，不含所有依赖或模型权重的授权审计。

| 候选与许可 | 可为我们所用的部分 | 推荐接法与优先级 | 验收重点 |
|---|---|---|---|
| [Docling](https://github.com/docling-project/docling)，MIT | PDF、扫描件、版面和表格解析 | P0，独立解析任务，把结果写回现有知识库 | 型号、数字、单位、表头和页码对得上；抽取结果先待核准；模型权重另核许可 |
| [Crawl4AI](https://github.com/unclecode/crawl4ai)，Apache-2.0 | 官网正文、链接、结构化资料采集 | P0，与 Docling 共用资料入库流程 | 保存来源 URL、时间和内容版本；抓取不等于完整 SEO 审计 |
| [IP Publisher](https://github.com/veeicwgy/ip-publisher)，MIT | 声明证据、审核报告、平台 payload、发布包契约 | P0，参考数据契约改进我们自己的内容流水线 | 发布包只是待分发成果；每个平台最终版本必须有审核记录 |

| [Postiz](https://github.com/gitroomhq/postiz-app)，AGPL-3.0 | 海外渠道授权、排期、API/webhook | P2，有海外客户后评估服务采购或独立部署 | 实际平台权限、配额、发布回执和许可边界 |

### 两个影响选型的具体发现

1. [OpenGEO 国内 provider 源码](https://github.com/cangqiaoGEO/opengeo-platform/blob/main/packages/lib/src/providers/registry/chinese-api.ts) 使用火山方舟、DashScope、DeepSeek API、腾讯 TokenHub 等端点。代码将 TokenHub 标作 Yuanbao，不能据此认为采集了元宝 App。DeepSeek 适配器明确无结构化 citations。我们必须按实际端点和观测方式命名，不能把模型 API 的回答展示为消费者 App 的真实排名。Kimi 不在此次确认的四个国内适配器内，另行验证。
2. [IP Publisher 的发布包](https://github.com/veeicwgy/ip-publisher/blob/main/docs/publish-package.md)包含平台正文、格式、封面描述、审核闸门和草稿同步信息。这比新建一套编辑后台更适合我们。我们还需补上企业、内容版本、附件校验值、审批人、目标账号、执行幂等键和平台回执。

许可处理：MIT/Apache 仍需保留相应声明；Crawl4AI README 对署名同时使用 recommended 与 must 表述，上线时核对锁定版本 LICENSE/NOTICE 并保留来源说明。GPL/AGPL 不应直接当作闭源白标代码拼入；独立部署也不能自动消除适用义务。[GEORank DATA_LICENSE](https://github.com/yaojingang/GEORank/blob/main/DATA_LICENSE.md)明确软件许可不授予独立的肖像、商标或代言权利。

## 4. 真正值得新增的能力，不再新增一级菜单

### A. 事实到内容的变更联动

知识库的品牌 IP 资产中保留产品事实层：型号、参数、单位、适用工况、认证、有效期、证据。参数修改或资料过期后，列出受影响的稿件与已发布页面，生成更新任务。人工核准事实是源头；PDF 解析和模型总结不能自行变成事实。这是制造业比通用写作工具更有价值的差异。

### B. 专家可执行，而不只是有性格文件

现有 10 个角色先不继续增加。第一条链仅激活知识、写作、审校和发布四种执行角色，由主管统筹。每次运行保存：企业/任务、Soul 版本、Skill 版本、模型、选用事实、工具调用、结果、成本和状态。

Soul 决定语气与协作方式；Skill 决定输入、步骤、输出和评测；服务端权限决定哪些数据和动作可用。不能靠提示词实现租户隔离。共享模型网关即可开始，不必先引入完整多智能体平台。

### C. 一份主稿，多份可核准的平台成果

技术主稿可派生官网产品页、知乎问答、公众号文章、图文卡片及视频脚本。平台适配允许调整结构和语气，不得改动参数事实。客户审核能看到每个目标平台最终效果；正文、封面、附件或咨询入口修改后，相关版本重新审核。后续资料更新能追踪到所有派生稿。

### D. 信源机会与付费媒介记录

放在矩阵分发内部，不做媒体商城。根据实际行业问题的引用证据，记录候选域名、被引用页面、内容相关性、投稿路径、报价日期、投放记录与公开 URL。行业协会、检测机构、行业垂直媒体和专业技术社区作为调研类别，不预先承诺每一家都有 AI 信任或低价。

付费采购前比较编辑审核、行业相关性、历史引用样本、报价和真实刊发形式。发布后核验 URL 与内容是否符合订单，再观察引用和询盘；付费刊发本身不能证明 GEO 增长。价格和媒体包必须有当期报价，目前不编造价格。

### E. 可解释的大屏与报告

大屏分三组：交付（核准稿、公开发布、失败/待处理）、GEO（有效样本、提及和引用、覆盖及更新时间）、客资（咨询、有效线索、跟进和销售回填结果）。所有数字能点开原始记录。

AI 提及、AI 引用、网站访问、表单线索和成交分别统计。UTM、referrer、表单与客户自述可作为来源证据，各有局限。不可把来源未知的流量归给 GEO，也不可把多平台总浏览量直接叫潜在客户。

## 5. 目前应该精简或暂缓的部分

- RAGFlow/Dify 等完整平台先不并装。当前缺口是解析、检索和模型调用，先局部补齐；复杂编排或大规模资料才重新评估。Dify 的多租户/品牌许可须另查。
- 不同时引入 Elmo、OpenGEO、GEORank 三套后台与客户体系。
- 视频先做真实素材整理、脚本和一个渠道投递；自动成片和复杂剪辑暂缓。
- Reddit/Instagram 洞察只对有受众需求的客户启用；通用底座先沉淀采购问题。
- 积分充值、媒体商城、复杂套餐和新增专家入口暂缓；内部先记录实际 token、采样、发布和人工处理成本。
- SEO 不独立扩成另一套大产品：先围绕产品页、选型页、案例、FAQ、索引检查和修复复测。结构化数据须与页面事实一致，llms.txt 不作为保证收录的交付。
- 不把“进入 AI 平台”设计成一键入驻承诺。核心是公开内容的可发现性与实际观测；Claude Code 是开发工具，应与 Claude 消费者产品和 API 分开定义。

## 6. 建议接入顺序与通过标准

这是一组工作阶段，不是未经估算的工期承诺。只选一家试点企业、一个产品系列，使用获授权资料与账号。

| 顺序 | 工作 | 通过标准 |
|---|---|---|
| 1 | Docling + 官网采集 + 事实核准 | 每项关键参数能回到文档页码或官网原文；不同企业不可互查 |
| 2 | 真实模型 + Skill + 发布包 + Promptfoo | 一份核准主稿及两份渠道版本；模型、来源、提示词和成本可追溯；关键事实与引用经核验 |
| 3 | WordPress + 一个国内渠道 | 官网正式 CMS 接口先跑通；国内优先评估蚁小二。区分已创建任务、草稿成功、公开发布；实际 URL 可验 |
| 4 | 官网表单/现有统计 + 客资跟进 | 测试咨询进入正确企业，能关联来源内容、去重、分配和回填；企微添加不能仅凭点击推断 |
| 5 | 固定问题集 + 小范围 GEO 基线与复测 | 相同问题版本、语言、地区和采集通道；保存回答/引用/失败与成本；API 和消费者产品分开报表 |
| 6 | 渠道扩展 + SEO 修复 + 信源试投 | 前述流程稳定后，再扩 P0/P1 渠道和付费媒介 |

阶段 1–5 构成最小真实交付链：

```text
官网/PDF → 核准事实与品牌表达 → 模型+Skill → 平台预览与审核
                                                    ↓
固定问题复测 ← 内容/来源记录 ← 公开 URL 回执 ← 可靠发布
                             ↓
                     官网咨询 → 客资跟进 → 客户报告
```

外部适配只返回结果到当前平台，由当前平台继续掌握企业 ID、审批、任务和审计。发布执行前重新检查审批版本；超时而结果未知时先核对平台状态，不盲目重发。浏览器账号按客户隔离，密钥不进入 Soul、提示词或日志。

对外试点前同步补齐：持久化队列/任务恢复、HTTPS、账号归属验证和找回、备份恢复、外部凭证保管、访问审计。当前 SQLite 与进程内调度可用于本机验证，不能直接等同多客户线上服务。

## 7. 选型结论

优先组合：当前业务底座 + Docling/Crawl4AI 资料层 + 一个真实生成接口 + IP Publisher 发布契约参考 + Promptfoo 评测 + WordPress/一个国内发布服务 + 单一 GEO 监测底座 + 现有统计或 Umami。

最有价值的产品能力是：企业事实可信、品牌表达一致、审批可控、发布可回执、客资能跟进、报告可追溯。新组件应补齐这些能力，不能只为增加功能名称而接入。
